## 2. R-01 剖切与测量（STR-003）✅

**SRS**：三维查看：旋转、缩放、平移、适配窗口、**剖切、测量**；P0。

**实现**
- 剖切：`#cutZ` 滑块（0–1.2 mm），`renderIso()` 按 `r.pts[0][2] > cutZ` 过滤整层；`#cutOut` 显示当前切面。
- 测量：`#measureMode` + `#measureOut`，2D 视图点两点用 `Math.hypot` 算真实 mm；测量点以黄点回显。

**验收（`test_57`）**
- 控件存在：`cutZ` / `measureMode` / `measureOut` / `cutOut` 各一份。
- 剖切**真的过滤层**（断言 `cutZ + 1e-9` 比较逻辑存在），不是只动滑块。
- 测距常数与文档一致：`hypot(60,40) = 72.11 mm`（`assertAlmostEqual`，防手写错）。

**文件**：`aepcb/web.py`

## 3. R-02 进度与取消（UI-005）✅

**SRS**：长任务显示进度与可取消；失败显示错误码、原因、建议；P0。

**实现**
- `aepcb/jobs.py`：进程内任务表 + 线程执行 + `cancel()` 协作式取消。
- `slicing.run(..., progress, should_cancel)`：道次边界检查取消、回报 `(i, total)`。
- `web.py`：`POST /api/job/slice`、`GET /api/job/<id>`、`POST /api/job/<id>/cancel`；前端 300 ms 轮询进度条 + 取消按钮。
- **取消后不写脏数据**：任务层 `rollback` 删除本次 `slice_set`（子表 `ON DELETE CASCADE`）。

**验收（`test_59`）**
- 进度单调 `[0,1,2,3]`，完成后 `progress=100`。
- 取消后 `status=cancelled`，且 **rollback 被调用 1 次**。
- 真实切片调用 `progress` ≥ 7 次，首个回调为 `(0, 7)`。

**文件**：`aepcb/jobs.py`（新增）、`aepcb/slicing.py`、`aepcb/web.py`

## 4. R-03 器件放置（CIR-002）✅

**SRS**：移动、旋转 0/90/180/270、翻面、锁定；支持栅格吸附与对齐；P0。

**实现**
- `routing.py`：`move/rotate/flip/lock_component` + `component_snapshot` / `apply_component_snapshot`。
- 旋转以器件中心为轴重算全部焊盘；翻面按中心 Y 镜像并同步 `pad.side`。
- `history.component_op`：反操作存**整器件快照**（增量在旋转+翻面叠加后会错位）。
- 锁定后移动/旋转/翻面直接拒绝并给出中文原因。
- 界面：器件表点选 + 移动(dx,dy)/旋转90°/翻面/锁定四按钮。

**验收（`test_58`）**
- 移动 (5,3) 后每个焊盘坐标同步偏移，误差 < 1e-6。
- 旋转 90°：`rot_deg` 累加，焊盘到中心距离不变（刚体，误差 < 1e-3）。
- 翻面：`side` 取反。
- 锁定后 `move` 抛 `ValueError`；撤销一步后 `locked` 回到 0。

**文件**：`aepcb/routing.py`、`aepcb/history.py`、`aepcb/web.py`

**补充（已完成）**：栅格吸附 + 对齐辅助线。
- 吸附：`snap_mm` 在**服务端**取整（前端吸附会让 API 与界面不一致），界面默认 0.5 mm；`test_60` 断言 1.7 → 1.5、0.3 → 0.5，不传 snap 时保留原位移。
- 对齐线：选中器件后，与其他器件同列（x 差 <0.5 mm）或同行（y 差 <0.5 mm）时画蓝色虚线。

## 7. R-06 性能实测（UI-009）✅

**SRS**：选择响应 ≤50 ms；非几何操作 ≤120 ms；三维 ≥30 fps（20 万面、基准机）；P0。

**实现**：`tools/ui_bench.py` —— 造 300 网络板，重复取中位数，输出 `workspace/ui_bench.md`。

**实测（本机 Intel Xeon Platinum 8255C @2.5 GHz / 3 核 / Python 3.12）**

| 指标 | 目标 | 实测 | 结论 |
|---|---|---|---|
| 选择响应 | ≤50 ms | **17.7 ms** | PASS |
| 非几何操作（改宽） | ≤120 ms | **3.2 ms** | PASS |
| 三维投影（20 万顶点） | ≥30 fps | **1.12 ms/帧 → 896.7 fps** | PASS（**仅计算**） |

**口径说明（必须一并引用）**
- 选择响应只测服务端 `web.state()`，**不含浏览器渲染**。
- 三维只测投影计算，**不含 SVG/DOM 渲染**。当前实现是 SVG 逐元素更新，该口径对它天然有利；真实浏览器里会更慢。
- 因此"896 fps"**不能**当作"浏览器里 20 万面 30 fps"的证据。若要在真实浏览器达标，正确做法是换 canvas/WebGL，而不是改阈值。
- 数据按本机记录（Intel Xeon 8255C / 3 核），**非 SRS 指定的 i5-12400**。
