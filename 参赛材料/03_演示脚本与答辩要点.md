# 演示脚本与答辩要点（5 分钟版 / 10 分钟版）

> 原则：每条主张后面跟一条**当场能跑**的命令；跑不出预期就说明主张不成立。

## 0. 开场（20 秒）

> "增材电子把 PCB 打样从开板蚀刻变成直接打印。但设计软件只管电气正确，切片软件只管路径——**能不能打出来**没人算。我们把这件判断变成可计算、可解释、可复放的。"

## 3. 评委可能追问（按五维准备）

**创新性**

- Q：这和现成切片软件（Cura/PrusaSlicer）有什么区别？
  A：它们从网格出发，只保证路径；我们从**网络与焊盘**出发，先判"能不能打"（R1–R7），再切片。跨层连通我们要求**必须有过孔**，图形重合不算通。
- Q：AI 在哪里？是不是只是规则？
  A：关键决策走规则引擎，因为验收要求"同输入同输出"；LLM 用在解释与建议排序，可关闭、可降级（`plan.degraded`）。这是刻意的取舍，不是没做。

**系统复杂性 / 技术复合性**

- Q：系统边界是什么？
  A：四域 + 数据模型 + 智能体 + 界面 + 真机协议。60 张表、666 字段、21 个触发器，SQLite 与 PostgreSQL 双份 DDL 均实跑。
- Q：怎么保证文档和库不脱节？
  A：Python DSL 是唯一事实源，DDL/字典/ER/追溯矩阵都是生成物，手改会被覆盖。

**商业价值 / 社会效益**

- Q：谁会用？
  A：高校实验室、中小硬件团队、产线换型。价值在"少打废版"和"换型有据可查"。
- Q：能省钱吗？
  A：首次可打印率提升靠规则前置拦截；Agent 4 轮内收敛，每轮有对比卡片，避免"改了不知道好坏"。

**功能完备性**

- Q：断网能演示吗？
  A：能。`doctor` 会显示可选依赖状态；智能体降级为本地规则集，全链不依赖云端。
- Q：数据可靠性？
  A：版本只追加不可改（触发器强制）；G-code 双哈希；工程包带整包哈希与清单，合并导入做 id 重映射。

**答辩表现**

- Q：最大的坑是什么？
  A：三个"不会报错"的错——连通性共享坐标节点导致跨层假连通、自动布线换层不打过孔、KiCad 封装旋转没补偿焊盘坐标。都是我们自己踩出来并写进测试的。
- Q：没做完的是什么？
  A：真机联调、STEP 完整 B-rep、KiCad 多层堆叠与盲埋孔工艺、基准机性能。边界写在申报书第 8 节，不藏。

## 5. 性能与代理模型（对应证据包第 6、7 节）

**UI 性能（UI-009）**

| 指标 | 目标 | 实测 | 口径 |
|---|---|---|---|
| 选择响应 | ≤50 ms | **17.7 ms** | 服务端 `state()` 返回，不含浏览器渲染 |
| 非几何操作（改宽） | ≤120 ms | **3.2 ms** | 含落库与操作栈 |
| 三维投影（20 万顶点） | ≥30 fps | **1.12 ms/帧** | **仅投影计算**，不含 SVG/DOM 渲染 |

被追问时必须主动补一句：

> “三维这一项只算投影，没算浏览器光栅化；当前渲染是 SVG 逐元素更新，真实浏览器里会更慢。要真正做到 20 万面 30 fps，得换 canvas/WebGL，不是改阈值。”

机器口径：Intel Xeon Platinum 8255C @2.5 GHz / 3 核（非 SRS 指定的 i5-12400）。

**代理模型（规则蒸馏）**

| 场景 | 结论 |
|---|---|
| 宽度扫描（5 候选） | 穷举 35.4 ms → 粗排+确认 **12.8 ms（2.77×）**，选择与规则最优一致 |
| Agent 每轮候选 | 规则 4 轮 89 ms vs 代理 4 轮 **174 ms** → **负收益，默认关闭** |
| 排序质量 | 分组留出 ρ **0.952**；成对排序 Top-1 **0.857**（回归仅 0.429） |

关于代理模型的标准答法：

> “我们做过，也用数据否定了它的一部分用途——它在 Agent 单候选场景是负收益，所以默认关闭；只有在宽度扫描这种 N 个候选比一次分的场景，才有 2.77× 的收益。这是取舍，不是堆功能。”
