# 增材电子一体化软件 · 数据模型（v1.0 完整版）

把需求规格说明书 v1.1 翻译成**可直接建库**的字段级数据模型：58 张表、645 个字段、108 个索引、21 个触发器，105 条需求全部有落点。

这份交付物的目标不是"画一张好看的 ER 图"，而是回答三个问题：**每个对象存在哪张表、受什么约束、凭什么验收**。

## 它是怎么做出来的

**单一事实源**：所有表定义在 `schema/*.py`，DDL、数据字典、ER 图、追溯矩阵四份产物由 `tools/` 生成。改字段只改一处，四份文档不会互相漂移。

```bash
python3 tools/gen_ddl.py     # 两份 DDL
python3 tools/gen_dict.py    # 数据字典（2494 行）
python3 tools/gen_er.py      # Mermaid + 两张 PNG
python3 tools/gen_trace.py   # 需求追溯矩阵
python3 tools/validate.py    # 建库 + 全链样例 + 33 项检查
```

## 校验结论

- **结构**：58 表全部建出、每表有主键、`integrity_check=ok`、`foreign_key_check` 为空。
- **不变量**：23 条，覆盖版本不可篡改、评分只追加、缺陷三元绑定、切片过期传播、路径穿越拒绝、分数区间、道次唯一等。
- **追溯**：SRS 105 条需求 0 缺口（92 落库 / 6 会话态 / 1 派生 / 5 非数据）。
- 详细证据：`06_校验/校验报告.md`。

## 已知缺口（不掩盖）

1. **T19-A 固定验收板的文件与哈希缺失**。SRS 7.2 说"随本文入库"，但正文与附件都没有。`accept_result.input_blob_hash` 已留位，**提交前必须补**，否则 T19 的"分数提升可复现"无法验证。
2. **PostgreSQL DDL 未实机执行**。本机无 PG 实例，只做了类型映射与语法静态检查；上线前需在目标版本跑一次。
3. **性能指标未测**（NFR-001）。数据模型层面只保证索引与主键体积可控，30 fps / 120 s 切片需在基准机器实测。
4. **界面契约不入库**。布局、选中、视图属会话态，刻意不落盘（见追溯矩阵 UI-00x）。

## 与旧版 ER 草稿的差别

旧版 22 张表、按"工程/结构/走线/不变量/切片/打印"五带排列，缺三类东西：**版本与撤销的载体**（`version_item`/`operation`/`snapshot`）、**追溯闭包**（`material_batch`→`deposit_pass`→`print_job`→`defect`→`attribution`）、**智能体证据**（`plan_step`/`tool_call`/`replay_run`/`diff_card`）。此外旧版把"层/道次"合成一张 `Layer`，无法表达"同一高度两个道次"（SLC-002/T13 直接挂）。

本版把这些补上，代价是表数从 22 涨到 58 —— 每一张的依据都在 `04_追溯/需求追溯矩阵.md` 第 5 节，可逐条反驳。
