# 需求冲突与取舍（分析底稿）

SRS v1.1 内部有 16 处需要裁定的地方。裁定结果已落进模型（见 `04_追溯/需求追溯矩阵.md` §6 的汇总表），本文记录**为什么这么裁、否掉了哪些方案**。

---

## 1. 四处会直接改变表结构的冲突

### C1 撤销到底产不产版本

- 冲突：PRJ-005「撤销不产生版本，版本号在撤销过程中不变」 vs DAT-002 验收要点「撤销通过新版本实现」。1.1 版变更记录第 3 条已裁定前者为准，但正文没改干净。
- 裁定：`version` 只在保存/提交/应用计划/回滚/导入时产生；撤销写 `operation(op_type='undo', undo_of_op_id=原操作)` 并应用 `inverse_json`。
- 否掉的方案：**撤销即新版本**。它会让"连续撤销 10 步"产生 10 个版本，PRJ-004 的历史列表被撤销操作淹没，且与 PRJ-005 的验收句直接冲突。
- 代价：`operation` 必须存反向操作；拖拽类操作的反向数据可能很大，所以留了 `inverse_blob_hash` 溢出到 CAS。

### C2 总厚 0.44 还是 0.35–0.40

- 冲突：1.7 工艺基线写"下保护 3×0.08 + 电路 0.10 + 上保护 0.10 = 0.44"，同一节又写"目标 0.35–0.40"；SLC-012 还把"总厚不一致"列为错误。
- 裁定：**层厚是唯一真值**，`slice_set.total_thickness_mm` 只记录合计值；`target_thickness_min/max_mm` 作为告警区间，超出只提示不报错。
- 否掉的方案：把目标区间当硬校验。那会让首版默认配置（0.44）一开始就无法切片，等于自锁。
- 遗留：待确认事项 9-1 仍需业务方给一个口径（是层厚要改，还是目标要改），模型两种都能接。

### C5 缺陷归因的对象

- 冲突：PRT-009 要求"缺陷关联到某个设计版本"，但作业绑定的是切片（SLC-010），中间隔了一层，且工程回滚后"经三跳推导"的归因会漂移。
- 裁定：`defect` 同时固化 `print_job_id` / `slice_set_id` / `design_version_id`，并用 `trg_defect_binding` 校验第三列必须等于切片的绑定版本；归因结论独立存 `attribution`（可复议、可推翻）。
- 否掉的方案：只存作业，查询时 join 推导。列表页每次三跳 join，且历史归因会随切片变更而"改口"。
- 代价：`defect` 有冗余列，写入时多一次校验；换来的是列表页单表查询与归因可审计。

### C6 内容寻址做不做

- 冲突：DAT-004（P0）要求"模型/路径/证据按内容寻址"，10.2 工时说明却写"只做保存/恢复/撤销栈，不做内容寻址"。
- 裁定：比赛版做**最小实现**——哈希去重 + 引用计数 + 校验状态；物理删除只做 dry-run，需显式触发并写 `blob_gc_log`。工程包一律内嵌被引用 blob，不假设对方机器有同样的 CAS 文件。
- 否掉的方案：完全不做内容寻址。那 DAT-005「外部改动后提示哈希不符」也无法实现，两条 P0 一起挂。

## 2. 其余十二处（摘要）

| # | 冲突 | 裁定 | 否掉的方案 |
|---|---|---|---|
| C3 | "恢复到关闭前" vs "恢复到最近成功版本" | 工作副本（operation+snapshot）与 version 分离，恢复时二选一 | 统一按"关闭前"，会让崩溃恢复把半成品当正式版本 |
| C4 | T19-A 哈希"随本文入库"但实际没有 | `accept_result.input_blob_hash` 留位，列为未关闭缺口 | 用任意样例板替代——会让"分数提升可复现"变成自证 |
| C7 | 规则版本是 P1 却被 T12 需要 | 规则版本表进 P0 最小范围，只把多版本切换 UI 留 P1 | 全后置，T12「阈值可配置」无载体 |
| C8 | 旧分数标注规则版本 vs 版本不可篡改 | 分数下沉 `mrc_run` 只追加；`version` 只留快照列 | 在 version 上加 `score` 列，重评分必然改写历史 |
| C9 | 规则与规则版本都声称持有阈值 | 阈值只属于版本下的明细行 | 阈值放规则本体，改阈值就无法版本化 |
| C10 | 布尔只预览却要求"失败可回滚" | 回滚按通用事务语义实现，不开放布尔执行 | 为 T05 开放布尔执行，违反 1.4 边界 |
| C11 | "工具"混用三种含义 | 拆 `tool_geometry`（几何）/`tool_registry`（能力）/`tool_version`（算法） | 一个字段兼容三种含义，重放比对必错 |
| C12 | 批次号何时写进 G-code 未定 | 切片提交时冻结进 `deposit_pass`，导出只读冻结值 | 导出时再解析，换批次会让"同输入哈希一致"失效 |
| C13 | 9-3 仍把作业/缺陷记录列为未决 | 按 P0 处理，9-3 视为已决 | 按 P1 处理，T18 无落点 |
| C14 | 单用户却要记"作者" | 只存 `author_kind` + `author_name`，不建用户表 | 建 users/roles，属于过度设计 |
| C15 | 走线定义"三维路径"，首版二维布线 | 存二维几何 + `layer_no/side`，z 由层推导，保留 `route.z_mm` | 强行存 z，二维编辑时 z 无处来 |
| C16 | DAT-001 列 21 类对象，4.1 有 25 行 | 以 4.1 为权威，DAT-001 改为引用 | 按 DAT-001 建表，漏会话/规则版本/工具几何/材料批次 |
