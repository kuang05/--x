# 需求 → 数据义务（分析底稿）

本文件是建模前的分析记录：把 SRS v1.1 的 105 条需求逐条问一遍"这条要求持久化什么、受什么约束"。最终落点是 `02_设计/数据模型设计说明书.md`，本文只保留结论与依据。

---

## 1. 按模块的义务摘要

| 模块 | 必须持久化的核心信息 | 隐含约束 |
|---|---|---|
| 工程与版本（PRJ） | 工程元数据、版本链、对象级差异、会话操作栈、快照、最近工程、设置 | 版本只追加不可篡改；撤销不产生版本；自动保存 ≠ 新版本；删除可恢复 |
| 结构（STR） | STEP 源文件指纹、单位换算、网格与容差、板框、特征树、布尔候选、诊断 | 显示与切片同一份网格；失败回滚保留上一版；候选不被静默应用 |
| 走线（CIR） | 器件位姿、焊盘、网络、走线几何（二维+层号）、跳线、禁布区、布局候选、连通性 | 位号/网络名唯一；越界与零长度拒写；失败不产生版本；层号必须预留 |
| 可打性（MRC） | 规则版本与阈值明细、工具几何、评分运行、违规条目、解释与建议 | 阈值只属于版本；分数只追加；同输入重复评分一致；同网不误报 |
| 切片（SLC） | 材料与批次、工艺配置、切片头、三层、七/八道次、路径、热历程、G-code 双哈希、估算 | 切片绑定设计版本；设计变更置过期但不删除；批次冻结后不可漂移 |
| 打印（PRT） | 设备与标定、作业状态机与阶段、事件时间线、两类暂停/续打、故障注入、缺陷、归因 | 故障 ≠ 缺陷；固化中断禁止直接续时；缺陷可追溯批次与版本 |
| 智能体（AGT） | 计划、步骤、工具调用、能力注册表、对比卡片、重放记录、授权级别快照 | 重放七要素固定；默认每步确认；没有隐藏能力；断网可降级 |
| 界面（UI） | 术语与错误码字典（其余为会话态） | 错误不以内部代号为唯一解释；离线可查 |
| 数据（DAT） | CAS 索引、外部文件指纹、工程包清单、迁移记录、设置 | 历史默认不物理删除；哈希必须校验；密钥不落工程 |
| 非功能（NFR） | 验收结果、降级记录、安全约束 | 性能/兼容性属测量，不建实体 |

## 3. 刻意不建模的东西

不是遗漏，是判断"不该存"：

| 不建 | 理由 |
|---|---|
| 飞线 / 面分析结果 | 由焊盘与网格实时派生，存了就有两份真相；需要缓存时按网格哈希进 `blob` |
| 选中对象、视图模式、面板状态 | 纯会话态，存了会变成"每次点击都写盘" |
| 用户表 / 权限表 | 单用户单工程（1.6-6），只区分 human/agent/system（见冲突 C14） |
| 密钥表 | 走系统凭据库，禁止落工程与日志（DAT-007） |
| 任务进度 / 通知 | 运行时状态；错误与结果分别落 `diagnostic` 与 `accept_result` |
| 独立审批表 | 步级确认落 `plan_step.confirm_*`，卡级决定落 `diff_card.decision`，两张表已覆盖 AGT-006 |

## 4. 体量核算

- 105 条需求 → 92 条有表承接，6 条会话态，1 条派生，5 条非数据，0 缺口。
- 58 张表里，SRS 4.1 直接给出的 25 行覆盖到 30 张（含拆分），其余 28 张是"验收必需但文档未列"的明细/证据表。
- 若要把 58 压到 40，可合并 7 处（`print_event`+`print_interruption`、`physical_layer` 并入 `deposit_pass`、`thermal_step` 并入 JSON、`version_item` 并入全量快照、`external_file` 并入 `blob`、`tool_call` 并入 `plan_step`、枚举全改 CHECK）。代价是：失去暂停类型强约束、层属性冗余、时间轴不可按行查、PRJ-004 无法做对象级 diff、DAT-005 语义混淆、重试痕迹丢失、加枚举值要重建表。**不建议**。
